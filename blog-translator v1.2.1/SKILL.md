# blog-translator

把日向坂46 / 樱坂46 成员的最新博客翻译成中文，输出「日文原文 + 中文译文」逐段对照的完整结果。

## 触发条件

用户输入同时包含：

- **触发词**：`blog 翻译`、`博客翻译`、`翻译 blog` 等；
- **成员名**：中文、日文或罗马音写法，例如「blog 翻译 髙桥未来虹」「blog 翻译 小坂菜绪」。

## 前置检查

1. 本 Skill 依赖 `web-access` Skill 提供联网抓取与浏览器操作能力（Node.js 22+、Chrome remote-debugging 已开启）。开始前确认 `web-access` 已加载且配置完成。
2. 确认本 Skill 目录下存在成员列表文件，缺失则提示用户补齐后结束：
   - `Hinatazaka Member List.md`（日向坂46）
   - `Sakurazaka Member List.md`（樱坂46）
3. 判断本次是否运行在 AstrBot 环境：宿主为 AstrBot（或其 agent 插件）、或宿主能够直接发送本地图片文件时，即视为 AstrBot 环境，**必须遵守「AstrBot 输出模式」**（见下文）。无法判断时，一律按 AstrBot 输出模式执行。
4. AstrBot 模式下先确认本地输出目录可写，默认为 `{本 Skill 目录}/output/`；无法创建或写入时提示用户后结束。

## 解析成员

1. 从用户输入中提取成员名（支持中文、日文、罗马音等常见写法）。
2. 分别在两个成员列表文件中查找匹配项：
   - 仅命中日向坂46 → 目标页 `https://www.hinatazaka46.com/s/official/diary/member?ima=0000`
   - 仅命中樱坂46 → 目标页 `https://sakurazaka46.com/s/s46/diary/blog/list?ima=0000`
   - 同时命中或都未命中 → 输出「未找到该成员，请确认成员名是否正确并重试」，结束流程。
3. 记录该成员的官方姓名，用于后续定位博客。

## 获取最新博客

官方博客依赖 JavaScript 渲染且图片可能懒加载，**必须使用 `web-access` 的浏览器 CDP 模式**：

1. 通过 CDP 新建 tab，导航到对应团体的博客列表页。
2. 在列表页找到该成员发布时间最新的一篇（按时间降序排列，第一篇即最新）。
3. 进入详情页，等待页面完全加载（含图片）；图片为懒加载时滚动到底部再等待。
4. 用 `/eval` 提取：博客标题、发布时间、正文纯文本与 HTML（保留段落结构和换行）、所有 `<img>` 的 `src`（含 `data-src` 等懒加载真实地址）。
5. 用上一步得到的真实地址把每张原图**抓取/下载为本地 png/jpg 文件**（见「5. 图片以本地图片文件输出」），并在输出前完成全部校验。
6. 页面要求登录时，按 `web-access` 的登录判断逻辑提示用户在 Chrome 中登录该网站后继续。

## 输出格式

### 1. 标题行

```
{成员姓名}｜{博客标题}（{YYYY.MM.DD}）
```

日期格式固定为 `YYYY.MM.DD`。

### 2. 正文：逐段对照

- **日文原文在上，中文译文紧接下一行，同一组内不空行**；组与组之间空一行。
- **日文原文与中文译文必须各自独占一行**，即原文一行结束后换行，译文从新的一行开始，例如：

  ```text
  ご卒業おめでとうございます🌸
  恭喜你毕业🌸
  ```

  严禁把原文与译文拼接、合并到同一行输出（如「ご卒業おめでとうございます🌸恭喜你毕业🌸」）。
- 在 Markdown 等会被渲染的环境中，需在日文行末加两个空格或使用 `<br>`，确保换行真实生效、渲染后不会被合并成一行。
- 原文与译文逐段一一对应，不合并、不拆分、不调换段落顺序。
- 语言为中文（简体），保持原文语气；由模型内置翻译能力完成，确保流畅自然。

### 3. 最大程度保留原文格式

- 保留原文的分段与段落内换行：原文在哪里断行、哪里空行，译文保持一致的断行与空行。
- 原样保留 emoji、颜文字、装饰符号、`♪`/`*` 之类的语气标记以及日文标点习惯。
- 不添加原文没有的标题、小标题、列表符号、加粗等排版；原文中的链接按原样保留。

### 4. 图片位置标记

- 在原文出现图片的位置插入独占一行的 `[图N]`（N 从 1 开始，按出现顺序编号），该行前后各空一行。
- 同一位置有多张图时按顺序分别编号。

### 5. 图片以本地图片文件输出

正文与结尾行输出完毕后，按编号顺序统一交付全部图片，且必须是**可直接保存的本地 png/jpg 文件**，而不是任何形式的链接：

- 先把原图抓取/下载到本地，目录为 `{本 Skill 目录}/output/{成员姓名}_{YYYYMMDD}/`，文件名为 `图{N}.jpg` 或 `图{N}.png`。
- 原图为 jpg/jpeg/png 时按原格式保存；webp、gif 等其它格式统一转换为 png（或 jpg）后再保存。
- 每个文件下载后必须校验：文件真实存在、大小 > 0、扩展名与真实图片格式一致。失败则重试一次，仍失败就在对应位置输出 `[图N]（下载失败）`。
- 交付时直接发送这些本地图片文件（宿主需要绝对路径时给出绝对路径），**禁止**输出图片的网络地址、Markdown 网络图片语法 `![图N](http…)`、页面地址或缩略图地址。
- 只有在宿主完全无法发送本地文件时，才退化为输出本地文件的绝对路径（依旧不得输出网络链接）。

### 6. 结尾固定行

```
来源：{原文链接} ｜ 日期：{发布日期} ｜ AI 译稿，非官方译文，仅供学习交流
```

## AstrBot 输出模式（在 AstrBot 中必须遵守）

本 Skill 运行在 AstrBot（或其 agent 插件）中时，除上述输出格式外，还必须同时满足以下两条硬性要求。

### A. 全部文字聚合为单个文本框，一次性输出

- 把「标题行 + 全文双语对照 + 结尾固定行」在本地拼装成一个**完整文本**；等正文、翻译、图片下载与校验**全部完成后**，一次性作为**单条消息**输出。
- 禁止拆分与流式输出：不得先发标题再发正文、不得按段落或按图片分批发送、不得连续发送多条消息；不得输出任何进度提示或中间消息（如「正在抓取博客…」「图片下载中…」）。
- 不得因为内容较长就自行分条。单条消息的长度上限交由平台处理（由平台截断或分条），Skill 本身只发一次完整文本。

### B. 图片以独立消息交付，只给本地 png/jpg 文件

- 正文中只在原图位置保留占位标记 `[图N]`，**文本中不得出现任何图片 URL**。
- 图片按「5. 图片以本地图片文件输出」抓取为本地文件（`output/{成员姓名}_{YYYYMMDD}/图{N}.jpg|png`），全部校验通过后再交付。
- 图片必须以「独立的图片消息」发送：文本全部走 A 节的单条文本消息，图片在文本之后**另起一条消息**，且图片消息内**不得包含任何文字**（不得与文本合并到同一条消息/同一消息链）。
- 发送顺序固定为：先发一条纯文本消息（标题行+双语正文+结尾行），再发一条纯图片消息（按 图1、图2… 顺序，可同条多图）。
- 严禁把 Plain 文本组件与 Image 组件放进同一次发送调用；即实现上必须是两次独立发送。
- 发送本地文件时确保接收端可直接保存为 png/jpg；宿主需要绝对路径时给出绝对路径。
- 严禁输出 Markdown 网络图片语法、图片直链、页面地址或缩略图地址；只有宿主完全无法发送本地文件时，才退化为输出本地文件的绝对路径。

## 操作流程示例（内部执行，不输出给用户）

假设用户输入：「blog 翻译 髙桥未来虹」

1. 匹配成员 → 日向坂46。
2. 打开 `https://www.hinatazaka46.com/s/official/diary/member?ima=0000`。
3. 在列表中查找「髙橋未来虹」的最新文章（可用 eval 获取全部文章卡片并按日期排序）。
4. 进入详情页。
5. 提取标题、日期、正文 HTML、图片地址。
6. 翻译正文。
7. 下载全部原图为本地 png/jpg 文件并逐张校验。
8. 按输出格式组装成单个完整文本，一次性输出，随后发送全部本地图片文件。

## 错误处理

- **成员未找到**：输出「未找到该成员，请确认成员名是否正确并重试」。
- **网络/页面加载失败**：输出「获取博客失败，请检查网络或稍后重试」。
- **无最新博客**：输出「该成员暂无最新博客」。
- **图片下载失败**：重试一次后仍失败，在对应位置输出 `[图N]（下载失败）`，其余文字与图片照常一次性输出。

## 注意事项

- 博客页面可能存在反爬机制，用 CDP 模拟真实浏览器访问可降低风险。

- AstrBot 模式下必须先完成全部图片的下载与校验，再一次性输出文本，避免出现「文字已发出、图片却失败」的中间状态。
- 翻译质量依赖 AI 模型，若译文不准确，请用户参考原文。
- 本 Skill 仅供学习交流，不用于商业用途。
